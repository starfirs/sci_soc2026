# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

An AI memory companion (Windows desktop, PyQt6). It captures screen text and audio during the day, consolidates it into a long-term memory graph at night, then quizzes the user the next day with feedback-driven spaced repetition.

`AI 记忆增强伙伴：系统设计方案.docx` at the repo root is the authoritative product/architecture spec. Milestone 1 — manual text → local scrubbing → cloud LLM consolidation → SQLite memory graph — the review closed loop (queue → generated card → feedback → reschedule), pre-generated daily cards, private PaddleOCR-json/RapidOCR-json screen capture, local Vosk audio capture, and a simple PyQt6 desktop pet are implemented in `backend/`.

## Architecture

Milestone 1 pipeline (`ingest_text` in `backend/pipeline.py`):

1. `backend/scrub.py` masks phone/email/ID-card/known names with stable placeholders; bank-card numbers are dropped per the design doc. Returns `(masked_text, {placeholder: real})`.
2. `backend/pipeline.py` persists new mappings to `placeholder_map`, inserts a `segment` row, then calls `memory.consolidate`.
3. `backend/memory.py::consolidate` runs two LLM calls — extract candidates, then decide create/merge/link/ignore/supersede — with a local top-5 similar-node retrieval in between. String similarity is character-bigram Jaccard for now; the design's local embedding model is not wired in yet.
4. All graph writes happen in one transaction; segments are marked `processed = 1` only on success. Calling it again with no unprocessed segments is a no-op.

Supporting modules:

- `backend/db.py` — SQLite schema: `segment`, `daily_summary`, `node`, `edge`, `review_log`, plus `placeholder_map`, `consolidation_report`, and the local `daily_card` cache. `connect()` initializes idempotently.
- `backend/review.py` — interval ladder `1,3,7,14,30,60,120`, feedback transitions, natural review.
- `backend/scheduler.py` — `select_due` / `get_today_queue` / `prepare_daily_cards` / `submit_feedback` / `set_node_importance` / `delete_node`. Queue priority is `(overdue / interval) × (0.5 + importance)` weighted by lapses; at most 8 cards/day. Card types map by step: 0-2 clue, 3 cloze, 4-5 scenario, 6 relation. `get_today_queue` prefers `daily_card` rows whose `step` and `content_hash` still match the node; missing cards are generated by the LLM or local templates. Passing `llm=None` uses local templates. Importance below 0.3 clears `due_at`; deletion cascades edges/review_log/daily_card and cleans `daily_summary.node_ids`.
- `backend/nightly.py` — nightly orchestrator: consolidates every date with `processed = 0` segments, then calls `prepare_daily_cards` for the day after `--date` (default today). Card generation failure falls back to local templates and is reported.
- `backend/review_cli.py` — interactive loop: question → reveal → `1/2/3` feedback; writes `node` review fields and `review_log` in one transaction.
- `backend/pet_controller.py` — Qt-free state machine (`load`, `current`, `reveal`, `feedback`, `skip`, `set_importance`, `delete_current`), unit-tested separately.
- `backend/desktop_pet.py` — PyQt6 frameless, always-on-top pet. Card loading/generation runs in a one-shot `CardWorker(QThread)` with its own SQLite connection. The worker emits cached/local cards immediately (`local_ready`), skips the LLM entirely when the queue is empty or every card came from `daily_card`, and only then tries cloud generation for missing cards; cloud cards replace the local ones only if the user has not started answering. On failure/timeout it keeps the local cards. UI state lives in `DesktopPet`; each card has 很重要/重要/一般/不重要 buttons, and “不重要” offers a confirmation dialog to delete the node. `--smoke-test` forces offline mode and auto-quits.
- `backend/capture_text.py` — shared capture-text cleanup for both screen and audio: CJK-space normalization, sensitive-line dropping (passwords/keys/JWTs/card numbers), character-bigram similarity, `scrub.mask`, and insertion of `segment(source=..., processed=0)`. Audio dedup spans `microphone`/`system` so the same utterance is not stored twice; screen dedup only compares screen segments.
- `backend/screen_capture.py` — automatic screen reading. Captures the foreground window's client area every 2 seconds by default (full screen with `--full-screen`), OCRs it only when a 16×16 aHash indicates the frame changed, then hands the text to `capture_text` for sensitive-line dropping, masking, and insertion. Default backend is `local` (project-private engine); `umi` uses the user's HTTP service and `windows` uses Windows.Media.Ocr/PyWinRT. Screenshots stay in memory. Default exclusions live in `DEFAULT_TITLE_KEYWORDS` / `DEFAULT_PROCESSES`; `data/screen_exclusions.json` appends rules. `--dry-run`, `--show-text`, and `--self-test` support manual verification. No tray indicator or pause hotkey yet.
- `backend/local_ocr.py` — private OCR engines. Launches `vendor/ocr_engines/paddle/PaddleOCR-json.exe` or `vendor/ocr_engines/rapid/RapidOCR-json.exe` as a hidden subprocess, speaks JSON over stdin/stdout, and passes Paddle `--enable_mkldnn=true` by default. Independent of any user-installed Umi-OCR (no shared ports/settings/processes). `--engine-dir`, `LOCAL_OCR_PADDLE_DIR`, and `LOCAL_OCR_RAPID_DIR` override locations; `--no-mkldnn` disables Paddle acceleration.
- `backend/setup_local_ocr.py` — copies Umi's `win7_x64_PaddleOCR-json` / `win7_x64_RapidOCR-json` plugin folders into gitignored `vendor/ocr_engines/`; `--check` verifies installation.
- `backend/umi_ocr.py` — optional Umi-OCR HTTP client for users who prefer their own running instance. `get_options` detects Paddle vs Rapid from option keys; `--ocr-engine` selects `UMI_OCR_PADDLE_URL` / `UMI_OCR_RAPID_URL` or verifies the active single-instance plugin. `read_mkldnn`/`set_mkldnn` inspect or write `UmiOCR-data/.settings` (`ocr.<plugin>.enable_mkldnn`); Paddle defaults to true, Rapid has no mkldnn. The HTTP API cannot switch engines per request, so both engines require either a GUI plugin switch or two ports/installs.
- `backend/audio_capture.py` — microphone + WASAPI loopback capture via `soundcard`, streamed as 16 kHz mono PCM into Vosk (`vosk-model-small-cn-0.22` by default). Vosk endpointing handles utterance boundaries and silence; one worker thread per source feeds the same model. Final transcripts go through `capture_text`. Audio never touches disk. `--wav` transcribes a 16 kHz mono WAV without a microphone; `--list-devices` and `--source` choose endpoints. Model lives under gitignored `models/`; see USAGE.md for download.
- `backend/llm.py` — `DeepSeekClient` over DeepSeek's Anthropic-compatible HTTP API using stdlib `urllib` (deliberately not the `anthropic` SDK: importing it costs ~8s on this machine). `complete_json` tolerates code fences/prose and retries once.
- `backend/config.py` — loads `.env`, resolves the DB path (`MEMORY_DB`, default `data/memory.db`), configures UTF-8 stdio.

Graph invariants:

- One `day` node per date; every memory node gets a `part_of` edge to it.
- `status` is `active` / `archived` / `superseded`; only active nodes are retrieved.
- `due_at` is `NULL` for `todo`, `person`, `day`, and nodes with importance < 0.3.
- New reviewable nodes start at `step = 0` and are due the next day.

## LLM configuration

`.env` (gitignored) supplies `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL` (DeepSeek's Anthropic-compatible endpoint), and `DEEPSEEK_MODEL`. Optional: `DEEPSEEK_MAX_TOKENS` (default 4096) and `DEEPSEEK_TIMEOUT` (default 30 seconds; on timeout the pet falls back to local templates).

**The model must be one the API key can access.** This key rejects `deepseek-chat` with a 403; `deepseek-flash` works. To inspect what is available:

```bash
python -X utf8 -c "
import json, os, urllib.request
from dotenv import load_dotenv
load_dotenv('.env')
req = urllib.request.Request(
    os.environ['ANTHROPIC_BASE_URL'].rstrip('/') + '/v1/models',
    headers={'x-api-key': os.environ['ANTHROPIC_AUTH_TOKEN'],
             'anthropic-version': '2023-06-01'},
)
print([m['id'] for m in json.load(urllib.request.urlopen(req))['data']])
"
```

Privacy boundary: only masked text is sent to the cloud. Raw names live only in `placeholder_map` (local SQLite); screen screenshots, raw OCR text, raw audio, and raw transcripts are never persisted. The default private OCR engine runs as a local child process and receives screenshots over stdin (the optional Umi HTTP backend uses `127.0.0.1`); neither is a cloud service. `.env`, `data/`, `models/`, `vendor/`, and `*.db` are gitignored. Never commit real keys or unmasked content.

Screen capture defaults to the foreground window's client area, so background password managers/banking pages are not read; `--full-screen` deliberately lifts that restriction. Exclusions match window title and process name. Lines containing passwords, API keys, JWTs, private keys, long tokens, or card numbers are dropped entirely before `scrub.mask` runs. Audio is streamed in memory and discarded after Vosk produces text; microphone/system duplicates are removed by text similarity.

## Testing

Tests live in `tests/` (96 total) and inject `FakeLLM` objects / a fake Umi HTTP server, so they never hit the network. `pytest.ini` puts the repo root on `PYTHONPATH`. The LLM-facing code path is only exercised by running a CLI against the real endpoint. UI verification: run the pet with `--smoke-test --screenshot <path>` (this forces offline card generation).

## Nightly card cache

`python -m backend.nightly` is the normal end-of-day step: it consolidates unprocessed segments, then writes the next day's cards to `daily_card`. The next day the pet and `review_cli` read those rows directly; the pet only contacts the cloud when a due node has no valid cached card. Cache rows are invalidated by a `step` change or a change to `title`/`content` (sha256 fingerprint). Running nightly twice replaces, rather than duplicates, the target date's rows.

## Not implemented yet

Higher-accuracy Whisper ASR, spaCy entity scrubbing, local embeddings, `memory.query`, system-tray/auto-start integration, automatic nightly scheduling, and capture pause/indicator controls. `todo` nodes do not yet get deadline reminders.
